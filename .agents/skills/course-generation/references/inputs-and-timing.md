# 信息源与时长

## 输入记录

`brief.json` 保存四项必要输入，以下是基于 Coach 公开说明的有效示例：

```json
{
  "sources": [{ "id": "readme", "location": "README.md", "scope": "编写内容、逐步展示、演讲与录制" }],
  "audience": "会阅读 Markdown、第一次用 Coach 录制讲解的开发者",
  "outcomes": ["能组织栏目和展示步骤", "能添加同步口播", "能选择表格、图示和动图"],
  "duration_minutes": 3,
  "language": "zh",
  "speaking_rate_min": 180,
  "speaking_rate_max": 240,
  "practice_seconds": 30,
  "pause_seconds": 15
}
```

四项必要输入不能以“普通人群”“了解知识”“适当时长”等无法判断的说法代替。来源可以有多个；记录版本、日期和允许使用的内容范围。代码课程核对同一版本的官方源码和文档，不混用不同版本的参数与路径。

## 来源对应

为每个步骤记录来源与教学用途，例如：

```json
{
  "opening": { "sources": ["readme"], "locator": "项目介绍" },
  "steps": [{ "number": 1, "sources": ["readme"], "locator": "编写内容", "purpose": "说明标题和栏目" }]
}
```

区分材料中的事实、教学重述、演示例子和学习者练习。新教学例子使用真实语法和可成立的前提，文字说明其示意用途。已有讲稿忠实转换时，来源对应原消息或段落编号；保留用户提问、错误答案与随后的解释顺序。

检查学习效果是否由来源支持，练习是否真正要求使用本节知识。生成期间遇到事实冲突，核实后使用有效表述；不要把纠错过程写进课程。

## 时长安排

先为学习目标分配讲述、看图、操作和反馈的时间，再写完整稿件。章节时间相加应满足用户的总时长；练习与停顿计入用户明确包含的范围。

中文估算以汉字数和英文词数分别计算；英文课程以英文词数计算。默认中文 180–240 字/分钟、英文 120–160 词/分钟仅用于初步估算，不代表讲述者实测速率。标识符、公式、数字与命令的读法会影响耗时，应在口播中写出实际讲法。可以在输入记录中设置已知语速。

`check-course.ts` 根据口播文本计算讲述区间，再加上 `practice_seconds` 和 `pause_seconds`。保留估算假设和偏离目标的提示。区间未覆盖目标时，调整受来源支持的解释、练习或活动预算，再运行检查；不要靠重复结论、界面提示或无关知识凑时间。

动图至少留出完整周期的观看时间。复杂图示沿同一条路径讲解，额外停顿计入 `pause_seconds`。互动录制以提问、预留思考时间、再给出解释的顺序编写，避免问题和答案立即连续读出。
