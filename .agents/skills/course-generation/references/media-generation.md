# 媒体生成与尺寸

## 根据教学任务选择形式

| 教学任务 | 形式与生成方法 |
| --- | --- |
| 说明物体外观、场景或视觉类比 | 使用可用的图像生成工具制作 PNG、JPEG 或 WebP |
| 说明步骤、依赖、分支或结构 | 编写 Mermaid，渲染为本地 SVG；保存 `.mmd` 图源 |
| 说明当前处理步骤 | 使用 `render-media.mjs` 生成节点强调 GIF |
| 说明运动或连续状态变化 | 使用视频生成工具或连续帧输出，再由 FFmpeg 编码为 GIF |
| 展示实际软件操作或实验 | 捕获真实运行画面，保存完整周期和原件 |

图像生成能力以当前可调用工具和实际输出格式为准。模型支持读取图片时，仍需确认是否有生成图片或视频的工具。只有单张图片输出工具时，可以逐帧生成并编码；帧之间需保持物体、背景、视角和文字一致。工具无法输出所需媒体时，说明缺少的能力，采用能够准确表达内容的 Mermaid 或已有来源素材。

## 生成图片

为图片准备简短设计说明：对应学习效果、当前展示步骤、要观察的对象、来源事实、画面比例、视觉风格、背景和重点。引用已有图片时说明需要保留的部分。

提示词写清实际教学内容，保持课程内配色与对象一致。复杂术语、代码和数值放在 Markdown 板书或 Mermaid 标签中；需要出现在位图内的文字逐项检查。图像生成后的物体结构、方向、数量、标签与来源事实逐项核对，必要时重新生成或编辑。

教学场景和视觉类比在图注或口播中说明示意用途。技术结构、接线关系、数据曲线和界面截图必须有来源依据；生成画面中的数字不能作为测量结果。

## 生成动图

先写状态顺序、每个状态的观察重点、持续时间和循环方式。一个循环只解释一个过程，口播留出至少一个完整周期的观看时间。

节点强调、路径推进和分支选择适合 Mermaid 教学动画。具有自然运动的场景可使用视频生成工具。逐帧生成时检查对象身份、位置变化与动作连续性，所有帧采用同一尺寸和视角。

使用 FFmpeg 从实际视频或帧序列编码。需要保留原动画每帧时，采用逐帧调色板，例如 `palettegen=stats_mode=single` 与 `paletteuse=new=1`，并检查输出帧数与时长。输出设置循环播放，避免把过渡闪烁或重置跳跃作为教学动作。

用浏览器观察至少一个完整循环，并查看两个不同状态；检查实际帧数、持续时间及循环信息。保存生成视频或帧序列、提示词和编码参数到课程的 `.artifacts/` 目录，板书引用最终 GIF。PDF 和 SVG 交付静态画面，动画文件随 Markdown 一起交付。

## 展示尺寸与文件大小

Coach 当前栏目宽度为 470px，图片按容器宽度缩放。生成前检查当前 `src/styles.css` 中的栏目和图片规则；以下尺寸作为起始建议，最终以真实画布检查为准。

| 项目 | 起始建议 |
| --- | --- |
| 普通位图 | 宽度 940–1410px，保证栏目显示时清晰 |
| 图片比例 | 优先 4:3 或 3:2；短流程可采用横向布局 |
| 单幅显示高度 | 尽量控制在 250–400px；按演讲画布的实际空间调整 |
| GIF 分辨率 | 宽度 700–940px，保持原比例 |
| GIF 周期与帧率 | 一个过程约 3–8 秒，通常 6–12fps；按动作需要调整 |
| 文件大小 | 普通图片尽量低于 1MB，GIF 尽量低于 5MB；超过时检查尺寸、时长和重复帧 |
| 图内文字 | 缩放到栏目宽度后，关键标签建议至少 16px；保持清晰可读 |

尺寸预算用于选择编码和组织内容。来源图片保留原件和必要细节；压缩后再次检查标签、边界和动画状态。透明背景用于需要与板书背景融合的对象，普通场景使用统一的浅色背景。

流程图按讲解顺序使用 `flowchart LR` 或 `flowchart TD`。宽图拆成关系概览与局部流程，高图按阶段分别展示；每张图都保留必要输入、输出和分支条件。避免依靠不断缩小字号容纳所有节点。先渲染，再按 Coach 中的实际显示宽度检查箭头、标签、图例和边缘是否完整。

对每项素材记录本地文件路径、用途、来源或生成工具、提示词、尺寸；动图额外记录帧率、周期和编码参数。分别验证当前步骤与全部显示，在演讲模式检查图片占用高度和同步口播。
