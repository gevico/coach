# 课程结构与展示规范

## 现有课程提炼的形式

| 形式 | 用途 | Coach 的组织方式 |
| --- | --- | --- |
| 大标题与前言 | 交代主题、学习任务和知识位置 | `#`、`preface:`、开场 `speaker:` |
| 分栏板书 | 按知识推进顺序讲解 | `##` 从左到右排列，`###` 分板块 |
| 关键词与列表 | 概念、条件、操作顺序 | 每个顶层列表项各占一步，嵌套项随父项显示 |
| 表格 | 比较同一组维度或建立映射 | 整张表占一步，附覆盖全部行列的口播 |
| 代码 | 展示真实语法、命令和参数 | 使用语言代码块，口播解释读法与必要条件 |
| 静态图 | 展示结构、关系、路径 | 保留原图；新示意图使用 Mermaid 渲染 |
| 生成图片 | 展示物体、场景、视觉类比 | 调用图像生成工具，核对教学事实与文字 |
| 动图 | 展示状态变化与过程 | 本地循环 GIF，完整捕获原动画或明确教学示意 |
| 提问与反馈 | 检查能否做出正确判断 | 问题、思考时间、回答和解释依次出现 |

这里提炼形式，不复用私人课程的标题、口播、图片或链接。通用示例以 Coach 自身的公开功能为内容。

## 板书与口播的关联

标题、段落、每个顶层列表项、代码块、图片、表格和引用各自构成展示步骤。口播注释附在对应单元之后。列表中的注释必须保留缩进：

```markdown
- **板书**：呈现需要观察的内容。
  <!-- speaker: 这一项说明板书承担的作用。 -->
- **口播**：解释当前内容。
  <!-- speaker: 这一项说明讲解如何跟随板书。 -->
```

栏目和板块标题也需要对应口播。长段落拆成有意义的展示单元，保持叙述连续；不要把同一句讲解反复附到多个步骤。

## 重点标记与代码

`:highlight[...]` 用于强调，`:circle[...]` 用于圈画，`:shade[...]` 用于底部色带。只标记本步讲解的词语，避免整段涂色。换行标题的色带应跟随每行文字。

命令放在 `bash` 代码块；配置、C、CMake 使用其真实语言。保留所有参数、括号和下划线。参数过长时按参数分组换行，续行的参数起点保持一致；在实际画布上检查，不只检查源文件空格。表格中的命令映射可展示语义，执行命令另给完整代码块。

## 图片、公式与动画

需要生成图片、动图或流程图时，阅读 [媒体生成与尺寸](media-generation.md)，选择实际可用的生成工具，并按栏目显示宽度检查比例和文字。

素材放在课程同名目录中，使用相对路径。公式保留文字语言、括号、箭头、数值顺序；没有公式渲染支持时导出图像。避免只复制可见文本导致 KaTeX 内容重复。

图示按从左到右、从上到下或沿箭头的固定路径讲解。保留图例、标签、附注和多个面板，裁剪时只去掉下载按钮等工具界面。

不要把 Mermaid 源码当作完成的图片。可运行 `render-media.mjs` 输出 SVG 和 GIF；其 GIF 是按节点依次强调的教学示意。原始系统演示应捕获真实播放周期，并保留原件。静态 SVG 不需要人为制作动画。

在浏览器中观察 GIF 两个不同状态，检查循环、清晰度和板书中的尺寸；GIF 文件扩展名不能证明播放正常。静态 PDF/SVG 导出无法承载完整动画，可同时交付 Markdown 和动图文件。
